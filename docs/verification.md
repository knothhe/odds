# 桌面验收

当前交付目标为 macOS 13+ / arm64。下列检查分别提供证据，不以离屏测试或成功构建代替安装及系统集成验收。

## 本地检查

`make check` 包含 Go 竞态测试、脚本回归、MyGo UI 检查与依赖清单过期检查。配置测试覆盖无版本文件、显式关闭、未知字段保留、未来 schema 只读及损坏文件；保存视觉测试使用可控后台写入器、正常动画与帧时钟，覆盖明暗外观、0/40/600ms 操作、失败重试、鼠标/键盘重复提交、后续编辑及成功后的尾帧。像素比较覆盖整个设置界面，仅允许既有状态文字区域变化；成功移除错误提示属于预期布局变化。

`make verify-native` 编译带 `e2e` tag 的独立预览程序，使用唯一单实例名称、私有配置和自动化 socket。检查中英文即时切换、窗口标题、双语原生菜单、真实原生关于控件、离线依赖、框架菜单语言、无控件焦点时的 ⌘W、关闭后隐藏、第二实例恢复聚焦、快捷键录制与 Escape 取消，以及正常退出。脚本不安装应用、不注册全局快捷键、不更改登录项；自动化插件不进入日常或正式构建。

结果位于忽略的 `dist/verification/native-result.json`、`native-general-en.png`、`native-general.png` 和 `native.log`。成功文件记录实际系统版本与架构；失败时保留相应日志和可取得的状态。HTML 设计入口在 `design/index.html`，原生离屏截图仍使用 `ODDS_UI_SCREENSHOTS`。

## 需要实际平台条件的检查

这些检查尚不能由预览模式证明。在独立测试账号或隔离的 Dev 安装中执行，保留配置副本和确切安装记录；不要用日常应用或真实数据制造失败。

| 场景 | 验收行为 |
| --- | --- |
| 全局快捷键 | 修改后实际触发；占用时显示失败；录制期间暂停，Esc/失焦/隐藏后恢复；退出释放注册。 |
| 系统登录项 | 在稳定安装路径启用/关闭；拒绝或待批准时反映实际系统状态；卸载后清理该安装登记，其他安装不受影响。 |
| 多显示器 | 在负坐标、不同缩放和拔掉原显示器后重开设置，标题和主要操作可达；鼠标居中按当前显示器工作。 |
| 最低系统 | 在 macOS 13 arm64 实机或 VM 验证正式包首次启动、设置、托盘与退出；新系统通过不代表最低系统通过。 |
| 安装与恢复 | 隔离路径检查 Dev/正式共存、覆盖安装、保留数据卸载、设置保存失败阻止退出，以及文件替换失败后的恢复。 |

## 首次正式发布之后

先确认完整 Release 已公开，再执行（以下以首次发布 v0.1.0 为例）：

```sh
make verify-public-update CURRENT_VERSION=0.0.0 EXPECTED_VERSION=0.1.0
```

版本参数必须指定真实预期版本，并严格递增。脚本从项目固定配置读取仓库和公钥，在临时 `.app` 中编译当前版本的 MyGo updater 检查程序，调用真实 `Updater.Check`、默认公开 Feed 及 odds 的认证下载器。固定同一次检查的候选，完整下载后核对签名、包内版本/身份/架构和路径，并在内存中读取已验证的构建记录。结果写入 `dist/verification/public-update.json`；失败退出非零，不用 fixture 或其他 Feed 代替。

这一步证明当前检查程序的原生检查和已认证下载，不调用 Install、不替换或启动下载的应用，也不证明历史已发布客户端、实际安装、启动健康或回滚。首个可升级版本发布后，还需用**实际旧版客户端**在隔离安装中完成待安装、重新启动、版本确认及失败恢复。二进制恢复不能代替数据格式兼容检查。

发布后用 `brew info --cask knothhe/tap/odds` 核对 tap 的最终版本，再在隔离账号完成首次安装、正常启动、升级和保留数据卸载。配方生成测试不能代替真实 cask 安装。
